# 小板凳游戏运营管理后台 V1 设计规范

日期：2026-09-30  
适用项目：XiaoBanDengGamePlatform（小板凳游戏平台）  
适用工程：XiaoBanDengGameWorkspace/admin-web  
开发主体：Freebooz Studio（Freebooz 工作室）

## 1. 目标与范围

本次采用“B 方案”：优先完成精美后台框架与核心业务页面，不在第一轮一次性铺开全部运营能力。

一期后台目标：
- 完成统一后台主框架重构。
- 完成品牌化登录页、综合工作台、用户中心、游戏中心、房间中心、对局中心。
- 建立后续商业中心、AI 中心、活动运营、客服风控、系统管理可直接复用的页面骨架和模块边界。
- 保持与现有 Go 业务后端一致，缺失的管理 API 采用明确的 Mock/占位接口，不伪造真实业务数据。
- 所有自研代码必须保留清晰中文注释。

不在本轮完整实现：
- 商业中心完整订单/退款/对账流程。
- AI 模型管理全功能。
- 活动运营完整配置器。
- 客服工单、风控策略、RBAC 全量权限管理。
- 多租户。

## 2. 视觉方向

选择“现代企业风”。

品牌视觉：
- 左侧栏：暖黑 / 深棕黑。
- 内容区：米白 / 浅暖灰。
- 主品牌强调色：小板凳橙金。
- 辅助色：深棕、浅金、状态色。
- 保留少量东方质感，但不采用重国风装饰。
- 页面整体紧凑、清晰、专业，避免大面积空白和营销官网式布局。

设计变量建议：
- 主品牌橙金：#D48A3A
- 高亮浅金：#F0B45A
- 深色侧栏：#181411
- 二级深棕：#2A211B
- 页面背景：#F5F2ED
- 卡片背景：#FFFDFC
- 主文字：#292521
- 次文字：#7D756E
- 边框：#E8E1D8

表格：
- 正文字号约 11px。
- 表头约 12px。
- 操作区紧凑。
- 行高适中，不做过度宽松排版。
- 表头尽量不换行。
- 支持固定筛选区、分页、抽屉详情。

## 5. 页面布局

统一三段式：

- 左侧：品牌 + 主导航。
- 顶部：面包屑、页面标题、页面说明、刷新/快捷操作、消息、管理员入口。
- 主体：统一 PageContainer（页面容器）。

标准业务页：
1. PageHeader（页面标题）
2. FilterBar（查询条件）
3. Toolbar（操作工具条）
4. DataTable（数据表格）
5. Pagination（分页）
6. DetailDrawer（右侧详情抽屉）

原则：
- 列表页尽量不跳转详情页。
- 用户、房间、对局点击后优先右侧抽屉。
- 复杂业务才进入二级独立页面。

## 6. 技术架构调整

现状问题：
- App.vue 同时负责布局、菜单、页面、接口数据。
- 未使用 Vue Router。
- 未使用 Pinia。
- 领域页面未拆分。
- API 仅 health/catalog/AI capabilities。
- Element Plus 基本为默认样式。

目标结构：

admin-web/src/
- app/
  - router/
  - store/
  - permission/
- layouts/
  - AdminLayout.vue
  - Sidebar.vue
  - HeaderBar.vue
  - PageContainer.vue
- modules/
  - auth/
  - dashboard/
  - users/
  - games/
  - rooms/
  - matches/
- components/
  - BrandLogo/
  - FilterBar/
  - DataTable/
  - DetailDrawer/
  - MetricCard/
  - StatusTag/
  - EmptyState/
- services/
  - api/
- assets/
  - brand/
- styles/
  - tokens.css
  - global.css

新增依赖：
- vue-router（Vue 路由）

## 8. 状态管理

Pinia 第一批：
- appStore：侧栏、主题、全局刷新。
- authStore：管理员会话、用户信息、开发 Mock 登录。
- platformStore：健康状态、游戏目录、平台基础配置。

领域页面自己的筛选和表格状态优先页面内管理，避免所有状态全塞 Pinia。

## 9. API 策略

已有接口继续使用：
- GET /health
- GET /api/v1/catalog
- GET /api/v1/ai/capabilities

后台核心页面需要补齐的管理 API，按真实后端能力分两类：

A. 可直接从已有服务补齐：
- 平台概览
- 产品/游戏目录
- 房间列表/详情
- 对局列表/详情

B. 当前数据模型不足：
- 用户完整管理
- 微信绑定详情
- 登录记录
- Event/Snapshot/Replay 深度查询

B 类第一轮允许 MockProvider（模拟数据提供者）辅助 UI 开发，但：
- 页面必须明显标记“开发数据”。
- 不得把 Mock 返回描述成生产真实数据。
- service 层必须可无缝切换真实 API。

## 10. 综合工作台

桌面优先布局：
- 第一行：4~6 个 MetricCard。
- 第二行：在线趋势 + 游戏分布。
- 第三行：一期产品运行状态 + 服务健康。
- 异常状态使用明显但不过度刺眼的告警卡。

一期关键指标：
- 注册用户
- 今日活跃
- 当前在线
- 实时房间
- 今日对局
- 象棋在线
- 贵阳麻将在线

后端无真实统计接口时，真实可用指标显示真实值；缺失指标显示“待接入”，不得伪造随机业务数字。

## 16. 响应式策略

主要目标：PC 1366×768、1440×900、1920×1080。

兼容：
- 1280px 宽后台正常使用。
- 侧栏可折叠。
- 表格允许横向滚动。
- 不以手机后台为一期目标。

## 17. 错误与空状态

统一处理：
- API 请求失败：页面内错误状态 + 重试。
- 无权限：预留 403。
- 无数据：品牌化 EmptyState。
- 后端未启动：工作台显示服务离线，不让整个后台白屏。
- Mock 数据：明显开发标识。

## 19. 本轮完成定义

完成标准不是“页面看起来更漂亮”，而是：
- 后台从单文件 Demo 结构升级为可持续扩展的模块化运营后台。
- 小板凳品牌视觉正式进入后台。
- 五个核心业务模块具备可运行页面。
- 公共页面组件、路由、状态管理和 API 分层建立。
- 后续商业/AI/运营模块可以在同一框架内继续开发，不需要再次重构主框架。
