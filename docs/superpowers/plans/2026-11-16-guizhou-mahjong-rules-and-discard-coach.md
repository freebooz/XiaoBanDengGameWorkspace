# 贵州地方麻将与出牌优选实施计划

> 执行时使用 Superpowers 的 subagent-driven-development 或 executing-plans 技能逐项落实。复选框用于记录实施与验收。

**目标**　小板凳先交付桌规清楚的贵州四人玩法，再扩展有规则依据的其他市州玩法。相同向听和进张时，牌效辅助能按本桌规则评估放铳、赠杠和靠张改良，推荐可解释的打出张。

**架构**　复用 Go 权威对局、房间快照、结算和牌谱链路。由服务端发布版本化预设与好友房选项，Godot 消费已锁定的桌规和合法动作，Rust 在本人可见信息上统一排序。

**技术栈**　Go 1.23、现有 HTTP/WebSocket 与 PostgreSQL、Godot 4.7、GDScript、Rust GDExtension。

**设计依据**　本文的地区证据、预设规格、房规和出牌排序。现状对照见[贵阳规则审查](../../MAHJONG_GUIYANG_RULE_AUDIT.md)、[向听与进张审计](../../mahjong-coach-algorithm-audit-20261116.md)和[原多玩法计划](2026-11-11-mahjong-rulesets.md)。

## 预设规格与交付顺序

**基线**　贵阳捉鸡 **guiyang@2.0.0** 和基础 **basic_108@1.0.0** 都是现有四人、万筒条 108 张、可碰杠不可吃的预设。贵阳默认接炮与抢补杠须本人已成杠，自摸可免杠。基础 108 默认无豆可接炮且无鸡分。两者在第一个有效胡牌窗口结算，当前允许同一炮多家胡。房间、快照、重连和旧牌谱按既有版本解析。 [现行预设](../../../server/internal/game/mahjong/guiyang/rules.go#L47) · [反应结算](../../../server/internal/game/mahjong/guiyang/game.go#L319)

**首个新增预设**　遵义定缺·试行 **zunyi_dingque@1.0.0**。以下是公开证据支持下的小板凳试行决策，尤其是选缺出牌约束、分数选取、翻鸡归属、荒庄豆分和首庄规则。展示时保留「试行」名称和完整房规。 [东胜遵义](https://k.sina.cn/article_6453054127_180a1caaf001003u1n.html) · [游戏茶苑遵义](https://wap.5158wan.com/mobile/detail/117) · [多乐遵义](https://www.duole.com/game/zhuojimj)

1. 四人 108 张，庄家 14 张、闲家 13 张，首庄使用对局种子随机选定。发牌后四家各选一门，全部提交后公布。超时选择手中张数最少的花色，同张数按万、筒、条顺序。
2. 手上还有定缺花色时，合法出牌限该花色。定缺花色不可组成副露或和牌。可碰、明杠、暗杠、补杠，不可吃。已定缺的席位即使摸回该门，也要重新清干净。
3. 自摸、平胡点炮均无需先杠，默认允许抢补杠。首个有效胡牌窗口结局，允许一炮多响。抢中时补杠未成立，原碰保留。赢家接庄，多响取从出牌者顺行最近的赢家，荒庄庄家连庄。
4. 牌型表采用平胡 3、七对和大对子 5、清一色和龙七对 10、清龙七对 20。多项命中时按最高单项计，平分时用固定牌型顺序。自摸由其他各席各付，点炮与抢补杠由责任席分别付每位赢家。点豆由放牌者付 3，闷豆与转弯豆由其他各席各付 3。热炮撤销紧邻该次出牌的成杠豆分。
5. 试行版开幺鸡及胡后翻鸡。下一张未摸牌同门顺位加一，九回一。幺鸡每张 1 分，可算本人未被取走的牌河。翻鸡每张 1 分，统计当前手牌、副露和获胜所用牌；同一实体为幺鸡兼翻鸡时只算一次。获胜牌可为同一炮的多个赢家计分。无余牌时只有固定鸡。两家有鸡时按各自鸡数相互结差。
6. 荒庄保留已成立的豆分，执行查叫，不结鸡。查叫以各座的定缺、牌型和公开可见牌库存确认有叫；仍有合法未见胡张的才收分。无叫者给每位有叫者其最高可胡牌型分，无叫且未缺门时按两倍支付。黑八、冲锋鸡、原缺额外分、报听与尾四强制胡在该试行版默认关闭。好友房先开放鸡分与抢补杠两个开关。

**下一批四人候选**　建议先做仁怀，接着做兴义和铜仁，安顺随黑八、原缺和查缺核分推进。各候选先以四人好友房和同规则训练验收。毕节、六盘水、都匀、凯里和其他县级模式完成规则取证后排入开发。

## 并列出牌优选

### 向听与进张

1. 对当前服务端允许打出的物理牌 ID，按牌种复用分析。在选缺、补杠响应、报听锁牌、等待其他席位等阶段，合法动作决定是否存在打出候选。
2. 模拟打出后计算结构向听 **S**，取本桌允许的四面一将、七对及龙七对等牌型最小值。**0 为结构听牌**。先杠、报听限制和实际胡牌来源另按规则判断。定缺手牌完整计入库存，但成牌目标排除所选缺门花色。
3. **U** 是所有能降向听的牌种的未见实体张数之和。每种牌的未见数 **R** 为牌池总数扣除本人暗手和去重的公开牌，模拟打出的牌继续计为已知。被碰杠取走的弃牌、最新出牌镜像、鸡牌事件镜像去重；其他人的暗杠只计组数，牌种保持未知。候选先按 **S 升序、U 降序** 排。13 张等效手牌显示整手值。对 0 向听，详情可再列本家自摸和接炮可用的牌种，按桌规标明接炮资格。 [向听与库存论文](https://arxiv.org/abs/2108.06832) · [现有 Rust 计算](../../../rust-core/src/coach.rs#L92)

### 放铳与靠张

- **先判断对每家是否可能放铳。** 使用实际房规、已成杠、已公布的定缺或报听、牌河、明副露与公开库存。严格先杠版对没有成杠的席位，本张即时接炮项记为规则阻断。以出牌本身作为和牌张，作将至少需一张未见同牌，作刻至少需两张，作顺子要有同门顺位的另两张，并满足副露数和定缺限制。特殊牌型按版本补充。所有补法都无法成立时才记为库存阻断。规则或快照字段缺失时标「信息不足」。曾经打过同张在本桌仍可能胡，过胡依该预设的生效与解除条件处理。
- **风险显著时先在同牌效候选中避险。** 首版可解释判据为对手已公开报听、已公开至少三副，或余牌不超过 8 张。对触发判据且可能接炮的对手按人数升序比较。其余局面先比较下一摸的收益和靠张，再比其余可能放铳的席位数与适用的明杠、鸡分暴露。8 张和三副是首版启发式参数，后续用贵州牌谱回测调整。风险原因只显示可解释的等级或依据。日麻 AI 的研究支持把对手听牌、命中该张与输分分开估计。 [Mizukami 与 Tsuruoka 对手建模](https://www.logos.t.u-tokyo.ac.jp/~tsuruoka/papers/cig2015mizukami.pdf)
- **进张质量 Q。** 在同 S、U 的组内，枚举第一张未见进张。对每个摸进分支模拟再打，仍按最小 S、最大 U 选择最佳后续状态。对处于听牌之前的候选，累加「该进张未见数 × 下一手有效张数」。听牌候选用本家按桌规可接炮的未见张数比较同分，Q 只参与听牌前的比较。
- **靠张改良 K。** 对每种不会立刻降向听的未见摸牌，模拟摸入再打。如果保持 S 且下一手 U 变大，累加「该摸牌未见数 × 增加的进张数」。两面搭子、复合搭子、孤张与对子由完整牌形和库存参与计算。用未见数作权重，模拟摸入后扣一，试打仍为已知。指标衡量下一摸后的机会，训练和复盘可说明具体靠张。 [Li 与 Yan 的多步打牌策略](https://arxiv.org/abs/1903.03294) · [Suphx 前瞻特征](https://arxiv.org/abs/2003.13590)
- **鸡豆及稳定排序。** 同牌效、同威胁且 Q、K 仍并列时，再比较其余接炮可能、能否放明杠，以及本桌确实会因打出和被认领而改变的鸡分。明杠项检查还有补牌、至少三张未见同牌及该席公开的合法条件。打出仍归本家的鸡按状态处理。最后用牌种和物理 ID 固定平局。等价的实体共享排名，按钮与高亮使用同一结果，只选中牌，玩家点击才提交。

**完整排序口径**　S 小 → U 大 → 强威胁可接炮人数少 → 听牌时可接炮的未见张多或听牌前 Q 大 → K 大 → 其他可接炮人数少 → 可放明杠的对手少 → 已知鸡分受损少 → 固定牌种和实体 ID。缺足够信息时保留结构效率和可求的改良项，并显示缺少的依据。目标是给出当前公开信息下的最优排序，实际放铳率需要同版牌谱校准。

## 全局约束与重点验收

- 版本同时覆盖合法动作、计分、终局及恢复语义。有结果差异时登记新版本。房间创建后锁定预设 ID、规则版本、选项 schema 版本及规范化有效选项，旧房按原版本继续。
- Go 服务端裁决准备、摸牌、胡牌、超时及结算。客户端仅使用自身与公开信息。选择候选、报听明示和选缺公开由所在玩法决定。牌谱在结算后按权限提供，历史房规可追溯。
- 首次绑定读取快照，后续由事件更新。断线、换房、重复消息和迟到结果按房局及动作窗口身份拒绝或去重。手动选牌、取消和出牌点击沿用现行操作。
- 重点验证同一炮多胡的实体与计分归属、定缺超时后断线恢复、旧选项反序列化与结算重发、鸡牌进出牌河以及同分推荐在可见信息变化后的稳定性。
- 手机竖屏入口、16:9 与 20:9 手机横屏、16:10 与 4:3 平板横屏、可调桌面窗口均需原生验收。覆盖切尺寸、长规则文案、真实点击、错误状态和安全区。移动联调使用既定 **api.xbd.freeboozstudio.test** HTTPS／WSS，从实际 Wi-Fi 设备验证 DNS、有效证书、登录与房间连接。调试客户端保持不限帧，记录实际垂直同步和帧率上限状态。
