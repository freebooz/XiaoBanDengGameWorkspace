# 小板凳麻将发布实施计划

**目标**　交付可发布的四人网络麻将。玩家能够登录、确认玩法、快速匹配或邀请好友、训练、完整行牌、断线回座、查看结算和战绩，再与原桌牌友继续。正式发布验收覆盖客户端安装包、运行环境及实际设备。

**架构**　沿用 Godot 三维桌面、Go 权威引擎、PostgreSQL 和 Redis。以版本化规则锁定房间，身份由服务端会话确定。客户端首次读取快照，之后通过连接、命令结果、房间和对局通知更新。三维视口保留可调画质。界面沿用原版木凳 Logo、柔和的乡村光照、缎面木纹主按钮和浅浮雕次按钮。

## A　会话与多人准入

- [x] 在 `server/internal/platform/account` 和 PostgreSQL 增加可恢复游客会话。创建账号与会话同一事务，服务端存摘要和到期时间。`POST /api/v1/auth/guest` 发放会话，`GET /api/v1/auth/session` 恢复本人身份。
- [x] 在 `server/internal/httpapi` 为麻将提供带会话校验的原生 WebSocket，身份绑定服务端账号。兼容麻将匹配 HTTP 入口也使用同一身份。其它游戏匹配状态与麻将分开管理。验证无凭据、过期、身份不符及房间跨游戏访问均无法读取或改动麻将状态。
- [x] 在 `mahjong_app.gd`、`mahjong_transport.gd` 和牌桌接通会话。按服务地址恢复本机账号，允许重开后回桌。会话失效有可理解的提示，网络错误保留可重试入口。令牌走请求头。
- [x] 验证 Go 测试、Godot 原生界面、四进程双局与真实 PostgreSQL 登录及重开恢复。隔离数据库确认四条独立会话摘要，首次登录和重启恢复共用四个账号。客户端截图见 `artifacts/mahjong_guiyang_series/brand_review`。

## B　好友房、匹配与弱网

- [x] 验证牌桌连接中断与半开恢复。通过心跳、重连、重新入座与原座快照恢复手牌和输入，四个原生进程完成真实出牌与续局。

- [x] 在 `matchmaking/mahjong.go`、麻将大厅及对局服务实现取消准备和成桌未入席处理。最后一位准备和取消准备由同一个房间状态机裁决。全员准备后 30 秒内需连接四席，超时好友房重置准备，快配释放全部席位，已连接的客户端收到退回通知。
- [x] 持久化好友房和快速匹配进行中的牌局、已接受命令、计时基准及房规。先提交首发和动作，再广播状态。隔离 PostgreSQL 和 Redis 上强制终止 API，由新进程恢复四个原座、私有手牌及合法操作，验证重复命令确认和恢复后继续行牌。
- [x] 大厅识别失联连接，保留等候席位 30 秒，恢复连接即撤销回收。席位提示由大厅快照驱动。
- [x] 持久化候场、入桌阶段和局间好友房。真实 API 重启验证部分准备、离房、首发前对局身份、四席结算快照和原房续局。好友房结算快照与公开战绩使用同一事务。
- [x] 实际中断 API 至 PostgreSQL 连接超过 15 秒，验证保存中暂停操作、恢复后原操作只提交一次以及下一次决策重新计时。
- [x] PostgreSQL 协议故障注入覆盖出牌提交后回执丢失，以及结算提交后、广播前 API 崩溃。验证只提交一次、原回执可重放、四席可恢复结算和同房续局。
- [x] 使用隔离 PostgreSQL 进行备份恢复演练，核对快照内容和时钟、原会话、四份手牌、历史复盘及恢复后继续行牌。记录单写入实例切换及回退步骤。
- [x] 好友邀请支持原生复制四位房号，加入界面提供触屏粘贴，读取和校验后由玩家确认加入。
- [x] 真实服务器验证快速匹配取消与重新排队，断网后从客户端返回原牌桌。邀请链接仍按发行渠道验收。

## C　结算、战绩与训练

- [x] 已完成牌局摘要入库与本人战绩接口。PostgreSQL 事务同时保存有效房规、结果、账号席位，重复提交幂等。数据库出现短时故障时后台有限次重试。服务崩溃、队列耗尽和长时故障下未提交摘要仍可能丢失，发布前需验证持久队列或事务化对局状态。
- [x] 大厅接入本人最近战绩。初次进入大厅、结算完成与返回大厅触发更新，按对局标识去重。真实服务四端完成两局后，重启的四个客户端分别从各自账号恢复两条战绩。
