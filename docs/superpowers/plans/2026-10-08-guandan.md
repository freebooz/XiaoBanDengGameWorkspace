# Guandan and Shared Poker Models Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task in the current workspace.

**Goal:** Add four-player Guandan and make all poker products use one editable and runtime model library.

**Architecture:** A shared Godot card factory owns models, texture selection and materials. A server-authoritative Guandan engine owns two decks, wildcard combinations, teams, ranking, leveling and tribute; the product shell uses existing account and room services.

**Tech Stack:** Go, Godot 4, Blender 5.2, PowerShell.

**Spec:** `docs/GUANDAN.md`

## Global Constraints

- One canonical poker model and texture source; preserve existing unrelated workspace changes.
- Four players, two decks, opposite teams, complete login/lobby/training/room flow.
- Hide opponents' hands and validate every submitted card ID on the server.
- Reopen saved Blender assets and test imported Godot nodes before claiming model reuse.

## Review Focus

- Duplicate cards have unique IDs but identical shared textures.
- Wildcards cannot become jokers; natural rank and level rank differ in sequences.
- Finished players are skipped, and the partner receives the lead only after the trick clears.
- Tribute is the highest eligible card and returned cards obey the return limit.
- Moving resources must leave the existing Landlord product importable.
