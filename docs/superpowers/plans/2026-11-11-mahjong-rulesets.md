# 小板凳麻将多玩法实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 大厅选择玩法后，匹配、四人牌桌、胡牌与计分实际执行该房间所锁定的规则，并能用两个可对照的玩法验收。

**Architecture:** 复用现有 Go 权威对局和 Godot 三维牌桌。服务端维护版本化玩法清单，开房时查表并绑定规则，牌桌依据房间记录创建引擎；客户端通过事件展示玩法、合法操作及结算。

**Tech Stack:** Go 1.23（项目声明）、HTTP / Gorilla WebSocket、Godot / GDScript、既有 PostgreSQL 初始化脚本。

**Spec:** 本文「首批玩法与规则口径」记录开发范围；初始行为以改造前代码和 [贵阳麻将移植记录](../../MAHJONG_PORT.md) 对照。

**实施进度：** 初审后已落地两套规则、玩法大厅、好友房、同规则训练和当前会话结果。状态推送与命令回执已接入；决策窗口编号、完整贵阳计分规则、多局与事件牌谱仍按计划分批推进。当前交付及验证见[大厅、好友房与训练房](../../MAHJONG_ONLINE_UI.md)。

## 全局约束

- 沿用 `ProductId=xbd_mahjong`、`GameId=mahjong`、四位房间号与现有三维桌、牌、操作资源。玩法由 `RuleSetId`、`RuleVersion` 定位。
- 服务端控制发牌、合法操作、超时、计分和结束条件。客户端可提交玩法标识与操作意图；服务端验证它们。暗手牌只发本人，其他人的暗杠、未摸牌墙与随机种子保持私有。
- 规则与版本在入队、开房、入座、重连和结算中一致；房间创建后锁定，既有房继续原规则。改变牌局结果时注册新版本。禁止未知版本回退到贵阳默认。
- UI 初次绑定消费完整快照，随后由状态、命令完成、连接和视口事件更新。UI 不以 Tick、常驻定时器或重复 HTTP 轮询查询匹配、准备、回合或网络状态。
- 原生验收先核对客户端协议、选定规则版本和实际运行的服务构建；调试和人工验证禁用人为帧率上限及垂直同步，记录实际状态。Windows 窗口比例、四端真实联机和 Android 实机分别验收。

## 首批玩法与规则口径

**推荐：共享流程 + 版本化预设。** 单纯增加设置菜单成本最低，但无法改变当前服务端行为；为每地复制一套引擎会重复维护匹配、超时、重连和保密。先在现有四人引擎内注入玩法定义，按实际差异拆出判胡资格、鸡分和结算策略，后续再扩展牌墙和阶段。快速匹配先选官方预设，便于玩家理解和避免队列过度分散。

| 规则项 | 贵阳捉鸡（当前基线 `guiyang@2.0.0`） | 基础 108（拟新增 `basic_108@1.0.0`） |
| --- | --- | --- |
| 人数、牌墙 | 四人，108 张万筒条，三骰开门 | 同左 |
| 操作与成牌 | 不吃；碰、三种杠、过；平胡、七对 | 同左 |
| 点炮／抢补杠胡 | 胡者须已完成一个杠 | 无已完成杠也可按合法牌型胡 |
| 自摸／点炮基础分 | 自摸其他三家各付 2；点炮／抢杠放牌方付 3 | 沿用此分值 |
| 杠分 | 完成的杠统一由其他三家各付 1 | 沿用此分值 |
| 鸡分 | 启用当前固定鸡、翻鸡、冲锋鸡与责任鸡处理 | 不产生鸡分、不消耗翻鸡牌 |
| 单局结束 | 第一次有胡的响应窗口结算（可一炮多响），或墙尽流局 | 同左 |

基础 108 是用于上线验证规则切换的轻量玩法，不冠地方规则名称。贵阳新版优先保留四人 108 张、不吃牌和首胡窗口结束本局；先冻结以下口径：平胡／大对子／清一色／七对／龙七对的基础分和叠加、无豆大牌能否接炮、抢杠／杠上开花／杠上炮、三类豆的付款对象、翻鸡取牌及同牌叠加、冲锋／责任鸡归属、是否过手限制、黄庄查叫及杠分退回。发布新版前把每项写成规则行和可核对的牌例。地方产品发布口径有差异，例如补杠的每家分值在 [多乐游戏运营团队说明](https://game.xiaomi.com/viewpoint/1291962525_1595496712801_11) 与 [同城游规则说明](https://m.tcy365.com/news/d35239.html) 中不同；这些资料可用于核对，项目应以确认后的规则表为准。

## Review Focus

- 同一账号仍在旧队列／房间时选另一玩法；取消成功才进入新队列，直接恢复旧房时清楚展示原玩法。任务 1、2。
- 同一响应窗口有多位候选，某一人先响应、另外两人同时响应或重连；各自仍可合法提交一次，前一窗口的操作和超时不能进新窗口。任务 2。
- 碰后未摸却满足胡牌形状；暗杠、明杠、补杠后的实际补摸仍可按牌型自摸。任务 0、1。
- 一张放炮牌被两位胡牌者引用、抢杠被胡、黄庄保留或撤销豆分；实体牌不重复、每局净分和为 0，记账只发生一次。任务 0、3。
- 切页、取消、换账号、断线后迟到事件、同版本重连和不同客户端协议；只消费当前连接与房间的快照，已销毁 UI 不复活。任务 2。
