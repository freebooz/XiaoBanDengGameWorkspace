| 顺序 | 改动 | 验收 |
| --- | --- | --- |
| 1 | 本地摸打使用有限 108 张实体牌墙 | 每种四张，发牌、抽牌、末张弃牌和重开守恒，离线原生入口可操作 |
| 2 | 联机动作关联决策窗口，响应截止时间保持固定 | 同窗口并发响应仍有效，旧窗口动作拒绝，保存和恢复后继续同一截止时间，老客户端可连接 |

| 4 | 同房续局和结算 | 核对庄家传递、换座或退房后的积分归属、累计和排名。旧房从开始记录累计的局数起展示覆盖范围 |
| 5 | 客户端规则入口和操作回归 | 版本由服务端目录驱动，结算和倒计时使用真实数据；检查出牌、三维进张、教学和续局尺寸 |

## 执行细则

1. 修改 `guiyang_3d_screen.gd` 的本地发牌、摸牌、结束与重开，复用标准实体牌墙。用 `mahjong_practice_wall_smoke.gd` 从正常大厅入口完成一整轮。教学复用共享 LOGO、右上角返回与标题木牌，使用同一用例检查点击和缩放。
2. 在 `mahjong_realtime.go` 与 `mahjong_checkpoint.go` 持久化决策窗口起点。私有快照随窗口发送 `action_window_id`，Godot 提交时回传。先识别已提交命令的重试，再核对当前窗口及截止时间。用 `mahjong_decision_window_test.go` 覆盖不同席位的同窗口响应、迟到命令、旧定时器、兼容旧客端及真实 PostgreSQL 恢复。
3. 在引擎加入 `guiyang@3.0.0` 独立版本，继续提供旧版。采用同城游的牌型基准番，明杠由放杠者付、暗杠与补杠分开，保留严格先杠及一炮多响。黄庄按有效听张查叫，热炮、抢补杠及黄庄撤销本局鸡杠分。以 `local_rules_test.go` 检查先杠、番型、鸡杠、过胡、过碰和恢复。此版本是项目选定的桌规，详见服务端规则与测试。 [同城游](https://m.tcy365.com/news/d1558.html) [多乐](https://game.xiaomi.com/viewpoint/1291962525_1595497217167_11) [双赢](https://doublewin.me/guides/mahjong-gz)
4. 将每局分差、下局庄家账号与持久化好友房一起写入。同一局仅累加一次。玩家离房后牌分仍归原账号，新入席从零开始，排名按当前四席排序，同分并列。赢家接庄、多响取离放炮者最近的赢家、流局留庄。庄家离房时由第一席接庄。无累计数据的旧房标明已统计局数，避免把后续局分显示为完整累计。
5. 逐局结算按参考图复用宣纸、竹边框、木牌标题和按钮。左侧准确显示胡法或流局，以及服务端给出的翻鸡指示牌。右侧优先显示本局牌分，保留鸡蛋收支、番型、查叫及好友房累计信息。沿用正常规则、续局及退回操作。用 `mahjong_series_ui_smoke.gd`、`mahjong_lobby_app_smoke.gd`、`mahjong_efficiency_overlay_smoke.gd` 验证数据与交互。
6. 用 `tools/compose-godot.ps1 -Product mahjong` 组合独立工程，运行全量 Go 回归、Godot 导入和原生 UI，验证手机、平板模拟比例和可调整 PC 窗口。用隔离 API 验证实际四席新规则进房、结算及续局，保留日志、截图、包版本与哈希。

## 后续完成条件

- 报听需要确定宣布条件、亮牌范围和锁牌行为后再实现。当前新版采用服务端计算的有效听张查叫。
- 血战到底和毕节三门牌各自需要完整的起手、胡牌、查叫和结算合同。实现后由服务端目录开放入口。
- 微信入口需要可用的应用配置与真实授权闭环。音量滑条、震动、自动准备、出牌确认、牌面选择和标签默认策略按独立 UI 回归验收。
