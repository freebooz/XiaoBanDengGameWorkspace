# 贵阳麻将四人连局与乡村界面实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans for implementation. Steps use checkbox syntax.

**Goal:** 同一台服务上的四位玩家能按贵阳捉鸡规则完成对局、回座、结算并在原好友房再开一局。

**Architecture:** Go 服务锁定玩法。好友房结算后清除准备状态并保留原座，续局创建新的对局 ID。Godot 的登录、大厅、等候房、三维牌桌、训练场和结算共用现有木凳 Logo、米色面板、柔光木纹与村景，从服务端事件读取业务数据。

**Tech Stack:** Go、Gorilla WebSocket、Godot 4 GDScript、现有立体牌模型、内置 imagegen。

**Spec:** `artifacts/mahjong_guiyang_series/concepts/` 中的竖屏和横屏构图稿。客户端使用柔光院落、原木凳 Logo、缎面木纹和米白控件，并显示实际房间、座位、牌和结算数据。

## 交付顺序

- [x] 保存并审看六张效果图以及无字乡村前景、横屏院落背景和柔光木纹按钮。
- [x] 后端保留好友房四座；四人重新准备才能开始新对局，旧动作不能影响新对局。快配与人机训练的结算流程仍可独立退出。
- [x] Godot 实现登录、大厅、等候房、独立训练场、横屏牌桌和结算，使用服务端通知更新界面与合法操作。
- [x] Go 回归；四个独立 Godot 进程在同一服务上完成贵阳房，检查保密发牌、暂离回桌、结算及同房再开。Vulkan 客户端读回帧率上限和垂直同步均为 0。
- [x] 检查原生截图和三种横屏比例，记录实际证据与联网步骤。实机、正式账号服务和公网部署留待各自环境验收。

## 边界用例

1. 有玩家已准备、另一位仍在结算，其他人不得提前开启下一局。
2. 房间里有人离开，剩余座位与准备数按服务器快照更新；满四后再开。
3. 第二局必须更换对局 ID、清空上一局的牌与分数；迟到动作不能串局。
4. 胡牌与流局都可结算；没有翻鸡牌时不画假牌。
5. 等候房和结算在切屏、断线、短窗口及规则弹窗返回时，保留真实状态与可触控的主操作。
