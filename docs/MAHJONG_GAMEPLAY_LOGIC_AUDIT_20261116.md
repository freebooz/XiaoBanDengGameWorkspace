# 小板凳麻将游戏逻辑审查

2026-11-16。审查覆盖登录与游客会话、大厅、快速匹配、好友房、训练、四人对局、离桌恢复、结算、再来一局、战绩和设置。四人主流程通过独立服务联调。贵阳捉鸡当前采用小板凳的严格先杠规则，地方番型和整桌规则仍有缺口。

## 回合操作

| 牌局状态 | 客户端操作与服务端判定 |
| --- | --- |
| 自己摸牌后 | 选择实体手牌，再点「打出」或再次点击已选牌。可用的暗杠、补杠和自摸由服务端给出。「过」不属于这个阶段。 |
| 自己碰牌后 | 由同一个座位打出一张手牌。此次碰牌没有摸牌，因此不能把碰进的牌当自摸。 |
| 他人出牌或提交补杠 | 只向有资格的座位提供响应。贵阳不吃牌，出牌响应可包含碰、明杠、胡或放弃。抢补杠响应可包含胡或放弃。「过」只放弃这次响应。 |
| 本家出牌超时 | 服务端实际移出一张手牌并写入弃牌区。有刚摸的牌时优先打出该牌。 |
| 响应超时 | 服务端结束未提交的响应，再按实际候选决定胡、杠、碰或下一家摸牌。 |
| 在途、重连、保存与结算 | 在途动作防重复提交。恢复后以原座位的私有快照恢复资格。保存中禁用操作，完局以已提交的结算快照显示结果。 |

动作行根据牌体的三维投影布置在手牌上方。选中的牌抬起时仍保有间距。教学动作区采用相同的上下顺序，并分别说明打出与放弃响应。服务端拒绝本家「过」时，回合、手牌、弃牌和状态代次均保持原值。 [客户端牌桌](../client/games/mahjong/guiyang/guiyang_3d_screen.gd) [权威回合](../server/internal/game/mahjong/guiyang/game.go) [服务端回归](../server/internal/game/mahjong/guiyang/game_test.go)

## 贵阳玩法的完成度

- 四人、万筒条 108 张、庄家 14 张和其余 13 张、不吃牌符合当前桌规。贵阳预设的接炮者本人必须已完成暗杠、明杠或补杠。自摸可无杠。启用抢补杠时同样执行严格先杠。基础 108 使用独立的胡牌资格和鸡分设置。 [项目规则核对](MAHJONG_GUIYANG_RULE_AUDIT.md)
- 当前成牌结构覆盖四面一将和七对。胡分统一为自摸其他三家各付 2、点炮者付 3。三种杠统一由其他三家各付 1。清一色、大对子、龙七对等独立番数和部分鸡分、热炮、杠开规则尚未实现。 [同城游规则](https://m.tcy365.com/news/d1558.html) [多乐开发者规则](https://game.xiaomi.com/viewpoint/1291962525_1595497217167_11)
- 已有翻鸡、幺鸡、冲锋鸡、责任鸡、可选黑八和一炮多响。黄庄查叫、同巡过胡及过碰、报听和金鸡倍率仍缺。公开版本对免豆大胡、抢杠及热炮有不同处理，小板凳当前采用用户指定的严格门槛。 [同城游算胡](https://m.tcy365.com/news/d30722.html) [同城游黄庄规则](https://m.tcy365.com/news/d25942.html)

## 尚需核对的行动时序

- 同一响应窗口每次有效提交都会更新最后行动时间，尚未应答的座位获得新的响应计时。多人响应时，一次弃牌的总等待可超过一个 15 秒窗口。 [服务器计时](../server/internal/httpapi/mahjong_realtime.go) [保存及提交时钟](../server/internal/httpapi/mahjong_checkpoint.go)
- 命令编号可防重复提交，局号可防跨局提交。`mahjong_action` 没有绑定正在响应的弃牌或补杠窗口标识。同一局中，极迟到的响应由接收时的状态判定。需要在继续支持旧客户端的前提下补齐窗口关联，并覆盖并发响应和断线回执。 [动作入口](../server/internal/httpapi/mahjong_realtime.go) [客户端提交](../client/games/mahjong/guiyang/guiyang_3d_screen.gd)
