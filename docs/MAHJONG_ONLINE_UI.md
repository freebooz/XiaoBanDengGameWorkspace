# 小板凳麻将：大厅、好友房与训练房

更新日期：2026-11-11。竞品依据、玩家路径和功能取舍见 [联机与界面调研](MAHJONG_ONLINE_RESEARCH.md)，规则版本与后续牌例见 [多玩法实施计划](superpowers/plans/2026-11-11-mahjong-rulesets.md)。

## 玩家流程

| 入口 | 本版行为 |
| --- | --- |
| 大厅 | 竖屏黑金翡翠主题，选玩法时展示规则摘要。快速开局、好友房、训练和最近战绩分区；连接、提交中、失败和待回桌均有真实状态。 |
| 快速开局 | 按玩法及版本匹配四人，四人准备后开局；可在开局前取消。 |
| 好友房 | 选玩法建房，复制四位房号；朋友输号入座，按建房时锁定的规则。四席显示真实入座和准备状态，满座且全部准备自动开局。 |
| 返回牌桌 | 已开局时可暂离，服务端继续托管；同一账号、服务进程仍在运行且本局未结束时，可以恢复原房与座位。 |
| 人机训练 | 一人加三位服务端电脑。使用所选预设、真实牌墙、出牌、碰杠胡和结算。人类决策时间 45 秒；离开可结束训练。 |
| 摸打练习 | 既有本地三维选牌、打出与补牌练习，作为独立入口。 |
| 结算和最近战绩 | 结算显示玩法、胡牌座位、四家净分，贵阳在有指示牌时显示翻鸡牌及计鸡值。大厅展示本次登录收到的实际结果，并标注来源。 |

## 两套权威规则

`guiyang@2.0.0` 为既有贵阳捉鸡：四人 108 张万筒条，不吃，普通点炮及抢补杠胡要求已有完成的杠，结算计鸡。 `basic_108@1.0.0` 共用四人 108 张牌桌，不需要已有的杠便可按成牌条件点炮／抢补杠胡，不翻鸡、不计鸡分。两者都以首个有效胡牌窗口结算，支持同一窗口多位胡牌。基础 108 是本产品的简化预设。

Go 规则清单生成服务目录，匹配、好友房及训练使用注册过的版本。引擎从服务端的房间记录创建，客户端进入牌桌再次核对规则 ID／版本。其他玩家暗手及牌墙保持私有。好友房和训练不参与公共匹配。

## 界面和状态

- 登录、竖屏大厅和等候房复用本项目的会所美术；横屏对局沿用三维桌和实体牌。基础 108 使用通用牌桌标识，训练席位明确标记为电脑。
- 首次订阅收到完整大厅快照，此后服务端推送入座、准备、开局、取消和结束。Godot 的传输节点处理底层 WebSocket I/O；大厅及牌桌只接收事件。客户端不再定时重复请求匹配和准备。
- 出牌确认按命令编号匹配，收到当前命令成功和更新后的牌局状态才恢复操作。服务器拒绝时保留仍有效的选牌。回合数字使用服务器截止时间驱动显示；断线清理显示并重新同步。
- 大厅每连接独立合并待发快照，慢写有超时。退出或销毁停掉连接、超时和显示动画。

## 验收方式

- 服务端从 `server/` 运行 `go test ./... -count=1`；实时测试只使用各自的本机回环临时端口。
- 生成 Godot 工程：`tools/compose-godot.ps1 mahjong`。客户端测试入口在 `client/tests/`，包括大厅控件、房间事件、牌桌规则／操作回执及既有选牌、语音、画质与练习回归。
- `TestMahjongNativeLobbyProduct` 可选启用：进程环境设置 `XBD_MAHJONG_SMOKE_GODOT` 为实际 Godot console 程序绝对路径；可设置 `XBD_MAHJONG_SMOKE_PREVIEW` 为项目内截图目录。它启动刚编译的 Go HTTP/WebSocket 处理器和一份 Godot 进程中的四套实际产品客户端会话。仅健康和游客账号创建由测试夹具提供，匹配、房间、牌局及结算走实际处理器。启动参数 `--disable-vsync --max-fps 0`，原生测试读回限制状态。
- 预览文件：`artifacts/mahjong_online/lobby.png`、`friend_room.png`、`friend_table.png`、`recent.png`、`training.png`。画面来自本机测试会话。
