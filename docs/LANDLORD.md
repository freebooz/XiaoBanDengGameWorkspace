# 小板凳斗地主

## 产品入口

- 产品清单：`products/landlord/product.json`。
- 使用 `tools/compose-godot.ps1 landlord` 生成 `client/.generated/landlord/project.godot`。
- 运行平台服务端后，在三个客户端分别游客登录、快速对局、准备；三人满座后进入实时牌桌。
- 大厅“单人训练”连接同一规则引擎，对手为两个基础电脑玩家。
- 登录页可设置服务端地址。手机、平板连接同一局域网服务端时使用服务端电脑的局域网地址。

### 乡村夜景登录页

登录页采用用户提供的乡村夜景设计，原生手机号和密码输入框、密码显示切换、木质按钮及服务器连接设置均可操作。当前开放游客认证；手机号、微信、注册和找回密码入口明确显示暂未开放。连接检查、重复点击、失败重试与手机/平板/PC 窗口验证见 [斗地主参考登录页](LANDLORD_LOGIN_UI.md)。

## 三维资源

- `tools/build_poker_models.py` 在 Blender 中创建公共牌桌和实心、圆角、有厚度的 63×88×1.3 毫米扑克牌；牌面、牌背各有独立 UV 面。
- 可编辑源文件：`SourceAssets/Poker/poker_card.blend`、`poker_table.blend`。
- Godot 资源：`client/game_framework/card3d/assets/models/poker_card.glb`、`poker_table.glb`。斗地主与掼蛋引用同一工厂、网格、牌面和材质，不保存游戏专属模型副本。
- `tools/build_poker_card_faces.ps1` 生成 54 张牌面和 1 张牌背纹理；客户端将每张牌面纹理贴到独立的三维牌模型。
- `tools/validate_poker_models.py` 重新打开 Blender 源文件和 GLB，检查尺寸、UV、对象层级及纹理数量。原有 `*_landlord_*` 工具作为兼容入口转调公共工具。

## 玩法范围

- 标准三人 54 张牌；每人 17 张，底牌 3 张。依次叫 0 至 3 分，全员不叫则重新发牌。
- 地主拿底牌并先手；支持单张、对子、三张、三带一、三带二、顺子、连对、飞机及带翅膀、四带二、炸弹、王炸。
- 服务端检查轮次、牌所有权、牌型和压牌大小；底牌在叫地主结束前隐藏，其他玩家手牌始终隐藏到结算。
- 两家不出后归还出牌权；炸弹和王炸翻倍，包含春天和反春天结算。
- 正式对局掉线后可在服务进程存活期间回到原座位。房间和训练状态目前保存在内存，服务重启不恢复。
- 训练电脑玩家采用基础应对策略，正式规则判定仍与房间对局共用服务端引擎。

## 横屏参考界面与按钮

对局采用 1440×810 横屏基准，手机宽屏和平板按实际比例扩展。园林背景、左右透明角色、真实木纹三维桌、下方大手牌、顶部底牌与倍数、彩色操作条按用户最新参考设计。进入对局自动横屏；返回大厅恢复原显示。黑桃、梅花和小王使用蓝色大牌点，红牌保持红色，两款扑克游戏共用唯一模型和牌面来源。

| 按钮 | 实际代码行为 |
| --- | --- |
| 抢地主 / 不抢 | 选择合法的 1、2、3 分，或发送 0 分；服务器检查当前座位和已叫分 |
| 加倍 / 不加倍 | 2.0.0 房间叫分后逐人决定一次；每次加倍使公共倍数乘 2，全部决定后地主先出 |
| 提示 / 出牌 / 不出 | 服务端返回可实际出牌的本人牌编号；选牌提交正式判型、压牌及轮次校验 |
| 理牌 / 收起 | 在点数、花色排序间切换并保留选中编号；真实显示/隐藏三维手牌 |
| 设置 | 低、中、高画质，实际音乐和音效开关，设置保存在本机 |
| 背包 | 免费蓝/绿/紫牌背与木桌/绿绒桌外观，实际应用并保存在本机 |
| 规则 / 退出 | 显示当前阶段及倍数规则；正式对局暂离后继续按服务器超时托管 |
| 聊天 / 表情 / 道具 | 预置内容及目标座位由服务端校验，同房间广播并防重复、限速 |
| 语音 | 按住录制、松开发送，最长 5 秒；原生麦克风输入、PCM16 编码、服务端校验和接收播放 |
| 战绩 | 仅保存实际收到的结算，包含训练标记、积分与倍数，相同结算不重复保存 |

当前产品规则版本为 2.0.0；权威匹配版本 1.0.0 的旧房间保持叫分后直接出牌。倒计时来自服务端实际 30 秒截止时间。背包为免费外观，本机战绩为结算记录，未模拟参考图中的金币、付费道具和 VIP 资产。

园林、透明角色和木纹使用内置图像生成工具制作并保存到 `client/games/landlord/assets/ui/`，生成提示记录在同目录 `ARTWORK.md`。它们用作背景、角色装饰和三维材质贴图；牌桌和扑克牌仍是可选、可操作的三维模型。

## 验证

- Go：在 `server/` 运行 `go test ./...`。
- Godot：生成工程后运行导入及 `res://modules/games/landlord/landlord_screen_smoke.gd`，检查三维模型节点和实际渲染。
- Blender：`blender -b --factory-startup --python tools/validate_poker_models.py`；结果写入 `SourceAssets/Poker/validation.json`。
- Android 包和真实手机、平板设备仍需实际导出与设备验收；当前已验证桌面 Godot 渲染。

横屏三端实际 Vulkan 截图见 `artifacts/landscape/landlord_*.png`。`landlord_buttons_smoke.gd` 检查合法/非法阶段、设置应用与持久化、工具面板、实际结算去重和退出；`landlord_live_flow_smoke.gd` 通过真实登录、大厅、训练、抢地主选择、加倍、提示、出牌、聊天回显和返回大厅。`server/cmd/landlord-smoke` 的三个真实账号在房间 5499 完成加倍后的整局（67 次出牌/不出动作）。

语音编码、播放及服务器最大长度已检查；真实手机麦克风权限、录音音质、设备性能和 Android 安装包仍需实体设备验收。截图和窗口比例验证运行于 Windows Godot，不能据此声称手机实机已验收。

### 2026-10-09 最终原生客户端复验

- `landlord_room_flow_smoke.gd`：三个实际产品壳在房间 7852 经登录、匹配、准备、各自私有手牌，使用真实界面按钮完成叫 3 分、三家加倍决定、同桌聊天广播、提示/出牌/不出直到结算；三端各保存一次战绩并返回大厅，恢复原显示。
- `landlord_live_flow_smoke.gd`：实际游客登录、大厅、训练、叫分、加倍、提示、出牌、聊天与返回大厅通过。实际训练截图为 `artifacts/landscape/landlord_training_live.png`。
- `landlord_voice_transport_smoke.gd`：原生 Godot 双向 256 KiB 缓冲通过真实服务器发送并接收最长五秒语音：8000 Hz 对应 106668 字符，16000 Hz 对应 213336 字符。验证数据为生成的 PCM 静音，未将其作为实体麦克风录音证明。
- `landlord_connection_smoke.gd`：缓存状态、连接未入座、入座未收到新快照均不允许操作；发送错误保留弹窗和选择，不虚报成功；空提示有明确回显。
- 图集预览注入固定牌局以比较比例；实际联机行为由以上独立测试验证。最终原生截图覆盖 844×390、1024×768、1440×810，按钮边界和三维视口比例检查通过。
