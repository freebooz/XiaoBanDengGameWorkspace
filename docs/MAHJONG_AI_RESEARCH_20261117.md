# 麻将辅助决策研究与实现边界（2026-11-17）

本次按论文原文、作者仓库及出版社资料核对算法，结合当前源码提出适合本项目的方案；不宣称文献检索无遗漏、算法全球最强，或已达到论文对局水平。

## 当前实现与本轮范围

`rust-core/src/coach/context.rs` 在本轮研究前已具备 Q/K 前瞻、公开信息风险、放杠风险和鸡分暴露评估，并非本轮新造这些能力。候选采用字典序：

1. 结构向听更小、未见有效进张更多；
2. 高威胁对手风险计数更少；
3. Q 更大，已听牌时改用接炮资格筛选后的未见等张数；
4. K 更大；
5. 其余风险、放杠风险、鸡分暴露依次更少；
6. 同值时使用稳定牌值顺序，实体选择继续服从服务器合法 ID。

Q 是有效首摸张数乘以后续最优弃牌进张数的加总；K 是非降向听摸牌中，维持向听并改善进张的增益加总。两者只对基准牌效并列候选展开，属于有限前瞻指标，不是归一化概率、完整两次摸牌胡率或论文算法的完整复现。“好形”应由整手改良路径体现，不能重复计算共享牌的局部搭子。

本轮核对现有排序与研究依据，并审计枚举合法性、回归和解释一致性。下文记录桌面验证；它不代替移动设备性能或真实四人对局验收。

## 规则适配与证据边界

当前服务端采用三门 108 张、不吃，未副露七对允许四张同牌计两对。贵阳接炮和抢补杠胡须本人已完成杠，自摸不限；3.0.0 另有过胡/过碰状态、多响、黄庄查叫及地方计分。应依据实际规则版本与上下文，不能套日麻振听、现物或七种不同对子公式。

未见牌包括对手暗手及未知牌墙，不能称为墙内精确剩余张数。前瞻须逐分支扣除摸入实体，弃牌不归还未见池，禁止枚举第五张同牌。公开信息风险目前是规则/库存排除和启发式分级，不是校准放炮率。接炮等张目前只覆盖已有上下文字段的资格筛选，不包含所有服务端过胡等状态，最终合法胡牌仍以服务端为准。

## 推荐方案与待做路线

当前保留基准向听、进张主序，再按高威胁、Q/K、其余风险、放杠、鸡暴露裁决并列；优先完善库存合法性、独立枚举校验、解释与事件刷新。此方案适合可解释牌效辅助，但不构成完整攻防最优策略。

完整攻防搜索、规则收益模型、对手后验和强化学习列为待做。它们需要本项目规则产生的数据、独立留出对局、同种子换座与多对手池，比较净分及风险，并报告不确定性。必要时防守应允许牺牲牌效，这需要独立策略目标与验证；不得把现有并列裁决直接宣称为该能力。训练和推理均须区分可见观察与隐藏真值，语言解释只陈述已有计算证据。

## 本轮修改与验证

- 有效牌枚举在模拟摸牌前检查牌种容量，阻止第五张同牌进入五进制缓存。已复现不合法搜索状态；未复现旧版本因此产生错误排名，不扩大缺陷结论。
- 原生桥接新增 `lookAheadEvaluated`，区分未展开搜索和已计算且 Q/K 为零。详情显示推荐排名及真实计算指标，明确它们不是胡牌概率。接炮候选也提示最终以服务端合法动作为准。
- Rust release 测试 **18/18 通过**，包括既有 600 组独立目标牌型枚举、逐分支扣库存/穷举后续弃牌 oracle、第五张守卫，以及论文同分例。该例独立枚举 12 条有序两摸路径得到 7/6 个成功结果，仅是指定库存的简化单人模型。
- Windows GDExtension release 构建通过；Godot 4.7.2 的 bridge、state、auto-selection、labels、efficiency-overlay、double-tap 六项回归通过。自动选择仍只选择服务器允许的实体，不自动提交，不覆盖同窗口的手动选择。
- RTX 4090 / Vulkan Mobile 原生渲染验证了推荐详情与自动选牌。详情截图 `.tmp/coach-context-godot-green/research-detail-native_tie.png` 使用明确构造的 Q160/K286 UI 数据；真实 Rust 排序和选择链由独立 `research-auto-selection-native.log` 验证，不能将详情截图当成真实联机分析证据。对应详情日志为 `research-overlay-native.log`。测试关闭 VSync、`max_fps=0`，未限制帧率。
- 两个固定上下文各运行 50 次：基础 108 的 p50/p95 为 **9.84/13.03 ms**；贵阳为 **7.77/11.66 ms**。这是桌面样例，不是最坏耗时或移动端结果。当前同步有限深度搜索尚无时间预算中断，移动端成本仍需实测。
